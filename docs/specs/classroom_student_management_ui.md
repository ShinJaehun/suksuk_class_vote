# 교실 학생 관리 UI

## 범위

`/classrooms/:id/students`의 학생 조회, 단일·일괄 추가, 개별·일괄 편집과 학교·교실 관리 화면에서의 진입/복귀 동선을 다룬다.

## 정책

- `Student.number`는 학급 안에서 고유한 영속 번호이며 빈 번호를 허용한다.
- 여러 학생 추가는 비연속 자연수 번호를 직접 입력할 수 있고, 행 이동 시 현재 번호 값을 함께 교환한다.
- 기존 학생 일괄 편집은 제출 학생의 번호 교환과 비어 있는 새 자연수 번호 입력을 허용한다. 미제출 학생의 번호는 사용할 수 없다.
- 일괄 편집은 전체 payload를 검증한 뒤 transaction 한 번으로 저장하며 부분 저장하지 않는다.
- Poll 시작 시 생성된 snapshot은 이후 Student 이름, 번호, active 변경과 독립적으로 유지한다.
- inactive School/Classroom에서는 기존 정책대로 Student mutation을 허용하지 않는다.

## UI 흐름

- 상단에는 학교, 학년·반, 담당 교사, 활성/전체 학생 수를 표시한다.
- 활성·비활성·전체 목록은 기존 관리 화면과 같은 버튼형 filter를 사용한다.
- 단일 추가 form은 목록 맨 위의 학생 row 형태 Turbo Frame에서 열고 닫으며 실패 오류도 frame 안에 표시한다.
- 개별 수정은 해당 학생 row Turbo Frame 안에서 처리하고, 성공 시 번호순 목록을 다시 렌더링한다.
- 여러 학생 추가는 학생 수 입력 후 행을 만들고, 행 이동·제외는 저장 전까지 DOM에서만 처리한다.
- 일괄 편집은 현재 filter 대상 중 제출된 학생의 이름과 번호를 한 번에 저장한다. 제외한 학생은 변경하지 않으며 행 이동 시 인접한 현재 번호 값을 함께 교환한다.
- 학교 상세와 학교별 교실 목록 링크만 제한된 return context를 전달한다. 직접 진입에는 돌아가기 링크를 표시하지 않는다.
- 작업 전체 성공·실패는 `application_flash`에 한 번 표시하고, bulk field 오류는 해당 row input 아래에 표시한다.
