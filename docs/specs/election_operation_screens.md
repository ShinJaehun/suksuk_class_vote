# 선거 운영 화면

## 목적

교실 선거 운영 화면을 두 화면으로 분리한다. 하나는 TV 또는 교사용 화면에 띄우는 공개/운영 화면이고, 다른 하나는 현재 참여자만 보는 투표 화면이다.

이 구조는 투표 흐름을 빠르게 유지하면서도, 교사와 학생들이 선거 진행 상태를 함께 확인할 수 있게 하기 위한 것이다.

## 공개/운영 화면

공개/운영 화면은 TV 모니터 또는 교사용 장치에 띄우는 상태판이다.

표시한다:

- 현재 참여자
- 전체 진행 상황
- 후보 목록
- 투표 참여자 명단 또는 종료된 선거의 투표 당시 참여자 명단
- 상태 점검과 운영 기록

표시하지 않는다:

- 진행 중 후보별 득표수
- 학생별 후보 선택 정보
- raw details JSON 또는 내부 id

투표용 후보 선택 버튼은 장기적으로 이 화면에서 분리한다.

### 목록 화면

`/polls`는 보관되지 않은 투표만 표시한다.
보관된 종료 투표는 기본 목록에서 숨기고 `/polls/archived`에서 확인한다.
`/polls/archived`는 `closed` 상태이면서 `archived_at`이 있는 투표만 표시한다.
보관된 투표도 상세 화면 `/polls/:id` 접근은 가능하다.
보관 해제는 아직 구현하지 않았다.

### 상세 화면 상태별 표시

`draft`는 준비 상태다.
투표 시작 가능 조건을 보여주고 삭제 버튼을 제공한다.

`in_progress`는 진행 상태다.
투표 화면 열기와 투표 중단을 제공한다.
삭제와 보관은 제공하지 않는다.

`stopped`는 중단 상태이며 결과 확정 상태가 아니다.
중단 안내, 투표 진행 상황, 투표자 명단, 삭제 버튼만 보여준다.
투표 화면 열기, 다음 투표자 진행, 결과 카드, 보관 버튼, 재시작은 제공하지 않는다.

`closed`는 종료 상태이며 결과와 기록 보존 대상이다.
결과를 보여주고 수동 보관 버튼과 삭제 버튼을 제공한다.
투표 화면 접근은 제공하지 않는다.

보관된 종료 투표는 `closed` 상태이면서 `archived_at`이 있는 투표다.
기본 목록에서는 숨기지만 상세 화면 접근은 가능하다.
보관 버튼, 삭제 버튼, 보관 해제는 제공하지 않는다.

## 투표 화면

투표 화면은 현재 참여자 한 명만 보는 단순한 화면이다.

표시한다:

- 현재 참여자 번호와 이름
- 후보 선택 버튼
- 필요할 경우 미참여 처리 버튼

표시하지 않는다:

- 전체 참여자 명단
- 운영 기록
- 후보별 득표수
- 학생별 후보 선택 정보

투표 화면은 최대한 단순하게 유지한다. 후보 선택은 불필요한 확인창으로 지연시키지 않는다.

## 동기화 방향

초기 구현은 route, action, view 분리부터 시작한다.

투표 제출은 우선 `Polls::SubmitVote`를 재사용한다.

공개/운영 화면 갱신은 후속 단계에서 Turbo Stream 또는 ActionCable로 검토한다. 이 첫 문서 커밋에서는 실시간 갱신을 구현하지 않는다.

## 이번 브랜치에서 하지 않는 것

- 후보자 1명 선거 정책
- 무투표 당선 또는 찬반 투표 mode
- PDF/export
- 보관 해제
- 종료 후 30일 자동 보관
- stopped 재시작
- `ResultArchive` 모델
- 학생별 후보 선택 저장, 표시, 로그
- 진행 중 후보별 득표수 공개

## 예상 커밋 흐름

1. 화면 역할 기준 문서를 추가한다.
2. 투표 화면 route, action, view를 추가한다.
3. 공개/운영 화면에 투표 화면 링크를 추가하고 상태판 역할을 정리한다.
4. 필요하면 request spec을 보강한다.
5. Turbo Stream 또는 ActionCable 갱신 방향을 검토하거나 문서화한다.
