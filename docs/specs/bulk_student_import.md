# Bulk Student Import

## 목적

이 문서는 `쑥쑥교실투표`의 학생/참여자 명단 bulk import 기능을 정의한다.

초기 목표는 파일 업로드가 아니라, 교사가 참여자 그룹 안에 학생 명단을 빠르게 등록할 수 있게 하는 것이다.
첫 구현은 학생 수를 입력한 뒤 그 수만큼 이름 입력칸을 제공하는 방식으로 시작하고, 이후 Excel 또는 HWP 표에서 학생 명단을 복사해 붙여넣는 방식을 확장한다.

이 기능은 추후 `쑥쑥칭찬통장`과 `책짹`의 교실/학생 bulk 등록 기능에도 재사용할 수 있는 실험 기능이다.

---

## 기본 방향

초기 MVP에서는 다음 방식을 먼저 구현한다.

```text
학생 수 입력
→ 학생 수만큼 이름 입력칸 표시
→ 교사가 이름 입력
→ ParticipantSlot으로 저장
```

현재 구현 상태:

- 참여자 그룹 상세 화면에서 “여러 명 추가”로 진입한다.
- 참여자 그룹 상세 화면에서 학생 이름 수정과 학생 삭제가 가능하다.
- 추가할 학생 수는 1명 이상 40명 이하로 제한한다.
- 기존 학생이 있으면 마지막 출석번호 다음 번호부터 입력칸을 표시한다.
- 이름 중 빈 값이 있으면 전체 저장하지 않는다.
- 저장 시 `ParticipantSlot` 번호를 순서대로 자동 부여한다.
- 학생 삭제 후 남은 학생 번호는 재정렬하지 않는다.

후속 bulk import에서는 다음 붙여넣기 방식을 제공한다.

```text
Excel/HWP 표에서 학생 명단 복사
→ textarea에 붙여넣기
→ 미리보기
→ 오류 확인
→ 저장
```

초기 MVP에서 하지 않는 것:

- HWP/HWPX 파일 직접 파싱
- XLSX 파일 직접 업로드
- CSV 업로드
- NEIS 원본 파일 직접 import
- 복잡한 열 매핑 UI

파일 업로드는 추후 필요할 때 검토한다.

## 입력 대상

초기 import 대상은 참여자 그룹이다.

참여자 그룹은 학급 선거에서 출석번호 순서로 투표를 진행하기 위한 학생 명단이다.

초기 필수 필드:

- 출석번호
- 이름

추후 확장 가능 필드:

- 성별
- 학년
- 반
- 비고
- 외부 학생 ID
- 쑥쑥칭찬통장/책짹 연동 ID

---

## 입력 예시

### 탭 구분

```text
번호    이름
1       김민준
2       이서연
3       박지호
```

### 공백 구분

```text
1 김민준
2 이서연
3 박지호
```

### 제목 행 없음

```text
1 김민준
2 이서연
3 박지호
```

### 추가 열 포함

```text
번호    이름    성별
1       김민준   남
2       이서연   여
3       박지호   남
```

초기 MVP에서는 출석번호와 이름만 사용하고 나머지 열은 무시할 수 있다.

## UI 흐름

### 1. 학생 수 입력 화면

교사는 추가할 학생 수를 입력한다.

예시:

```text
추가할 학생 수: 25
```

버튼:

```text
[입력칸 만들기]
```

---

### 2. 학생 이름 입력 화면

시스템은 학생 수만큼 이름 입력칸을 표시한다.

예시:

```text
1번 [        ]
2번 [        ]
3번 [        ]
```

교사가 이름을 입력한 뒤 저장하면 `ParticipantSlot`으로 저장한다.

---

### 후속. 붙여넣기 화면

교사는 안내 문구를 보고 명단을 붙여넣는다.

예시 안내:

```text
Excel 또는 HWP 표에서 출석번호와 이름 열을 복사해 아래에 붙여넣으세요.

예시:
1    김민준
2    이서연
3    박지호
```

버튼:

```text
[미리보기]
```

---

### 후속. 미리보기 화면

시스템은 저장 전 파싱 결과를 보여준다.

예시:

```text
가져올 학생 명단

번호 | 이름   | 상태
1    | 김민준 | 정상
2    | 이서연 | 정상
3    | 박지호 | 정상
4    |        | 이름 없음
```

오류가 있으면 저장 버튼을 비활성화하거나, 오류 행 제외 후 저장 여부를 명확히 선택하게 한다.

초기 MVP에서는 오류가 있으면 저장하지 않는 쪽을 기본으로 한다.

---

### 후속. 저장

교사가 미리보기를 확인한 뒤 저장한다.

저장 후 참여자 그룹 상세 화면으로 이동한다.

---

## 파싱 규칙 초안

초기 파서는 단순하고 예측 가능해야 한다.

규칙:

1. 입력값을 줄 단위로 나눈다.
2. 빈 줄은 무시한다.
3. 각 줄은 탭, 쉼표, 여러 칸 공백 중 하나로 분리한다.
4. 첫 줄이 제목 행으로 보이면 건너뛴다.
5. 첫 번째 숫자 값을 출석번호로 본다.
6. 출석번호 다음 텍스트 값을 이름으로 본다.
7. 이름 뒤의 추가 열은 초기 MVP에서 무시한다.
8. 출석번호가 없으면 오류 처리한다.
9. 이름이 없으면 오류 처리한다.
10. 출석번호가 중복되면 오류 처리한다.

---

## 제목 행 판단

다음 단어가 포함된 행은 제목 행으로 볼 수 있다.

- 번호
- 출석번호
- 이름
- 성명
- 학생명
- 성별

예시:

```text
번호 이름
출석번호 성명
번호 이름 성별
```

제목 행 판단이 애매한 경우에는 무리하게 추측하지 않는다.

---

## 검증 규칙

각 row는 다음 조건을 만족해야 한다.

- 출석번호가 존재한다.
- 출석번호는 양의 정수다.
- 이름이 존재한다.
- 같은 입력 안에서 출석번호가 중복되지 않는다.
- 같은 참여자 그룹 안에서 출석번호가 중복되지 않는다.

초기 MVP에서는 동명이인은 허용한다.

---

## 오류 표시

미리보기에서 오류를 명확하게 보여준다.

예시 오류:

- 출석번호 없음
- 이름 없음
- 출석번호 중복
- 출석번호가 숫자가 아님
- 이미 등록된 번호

예시:

```text
번호 | 이름   | 상태
1    | 김민준 | 정상
2    | 이서연 | 정상
2    | 박지호 | 오류: 출석번호 중복
4    |        | 오류: 이름 없음
```

---

## 저장 정책

초기 MVP에서는 전체 성공 또는 전체 실패 방식으로 간다.

즉, 오류가 하나라도 있으면 저장하지 않는다.

이유:

- 교사에게 예측 가능하다.
- 실수로 일부만 등록되는 문제를 막을 수 있다.
- 초기 구현이 단순하다.

추후 확장:

- 오류 행 제외 후 정상 행만 저장
- 기존 명단과 병합
- 기존 명단 교체
- 중복 학생 업데이트

---

## 학생 명단 수정/삭제 정책

현재 단계에서 `ParticipantGroup`은 아직 선거와 연결되지 않은 원본 명단이다.
따라서 교사는 본인이 소유한 참여자 그룹에 학생을 추가할 수 있고, admin은 전체 참여자 그룹에 접근할 수 있다.

### 선거에 연결되기 전

선거에 아직 사용되지 않은 참여자 그룹은 명단을 정리할 수 있는 상태로 본다.

허용 방향:

- 학생 1명 추가
- 여러 명 bulk 추가
- 학생 이름 수정
- 학생 삭제

주의:

- 출석번호 재정렬은 투표 진행 순서와 직접 연결되므로 신중히 검토한다.
- 현재 구현은 학생 1명 추가와 학생 수 기반 bulk 추가까지만 제공한다.
- 이름 수정과 삭제는 구현되어 있다.
- 번호 재정렬은 아직 구현하지 않는다.

### 선거가 생성된 뒤

참여자 그룹은 원본 명단이다.
draft 선거는 아직 `PollParticipant` snapshot이 없고 원본 참여자 그룹을 직접 참조한다.
draft 상태에서도 원본 명단 이름 수정, 학생 추가, 학생 이름 수정, 학생 삭제는 허용한다.
단, draft 선거가 현재 참조 중인 원본 참여자 그룹 자체 삭제는 차단한다.
이 삭제 차단은 비밀투표나 결과 보존 때문이 아니라, 준비 중인 Poll이 필수 명단 설정을 잃지 않게 하는 안전장치다.

정책 방향:

- 선거 생성 시점에는 원본 `ParticipantGroup`만 연결한다.
- 투표 참여자 명단 snapshot은 선거 시작 시점에 만든다.
- draft 선거가 현재 참조 중인 원본 명단 자체 삭제는 제한한다.

### 투표가 시작된 뒤

투표가 시작된 뒤에는 `PollParticipant` snapshot이 투표 진행 기준이다.
따라서 진행 중/종료된 투표가 있어도 원본 참여자 그룹 이름 수정, 학생 추가, 학생 이름 수정, 학생 삭제, 원본 명단 삭제는 가능하다.

이유:

- 시작 시점의 출석번호와 이름은 `PollParticipant.number/name`에 보존된다.
- 원본 명단 변경은 이미 시작된 투표의 복구, 중복 제출 방지, 결과 보존에 영향을 주지 않는다.

### 투표 종료 후

투표 종료 후에도 결과 보존 기준은 `PollParticipant` snapshot이다.
종료된 투표는 원본 참여자 그룹 또는 학생 row가 수정/삭제되어도 `PollParticipant.number/name` 기준으로 투표 당시 명단을 유지한다.

## 데이터 모델과의 관계

초기 구현에서는 import 결과가 참여자 그룹의 participant slots로 저장된다.

개념:

```text
ParticipantGroup
- name
- teacher_id

ParticipantSlot
- participant_group_id
- number
- name
```

실제 모델명은 구현 과정에서 바뀔 수 있다.

중요한 점은 학생을 로그인 계정으로 만들지 않는다는 것이다.

초기 MVP에서 import된 학생은 인증 주체가 아니라 투표 진행을 위한 명단 데이터다.

## 재사용 가능성

이 기능은 다른 프로젝트에도 재사용 가능해야 한다.

예상 재사용 대상:

- 쑥쑥칭찬통장
  - 학급 학생 일괄 생성

- 책짹
  - 교실/그룹 학생 일괄 등록

따라서 파서 로직은 특정 선거 도메인에 과하게 묶지 않는 것이 좋다.

가능한 구조:

```text
BulkStudentImport::Parser
BulkStudentImport::Preview
BulkStudentImport::Commit
```

다만 초기 MVP에서 과도한 추상화는 피한다.  
먼저 단순 구현 후, 재사용 필요가 분명해졌을 때 분리한다.

## 테스트 우선순위

우선 테스트할 항목:

- 탭 구분 입력을 파싱한다.
- 공백 구분 입력을 파싱한다.
- 제목 행을 건너뛴다.
- 빈 줄을 무시한다.
- 출석번호 중복을 오류로 표시한다.
- 이름 없음 row를 오류로 표시한다.
- 번호 없음 row를 오류로 표시한다.
- 오류가 있으면 저장하지 않는다.
- 정상 입력은 participant slots로 저장된다.
