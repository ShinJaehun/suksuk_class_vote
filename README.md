# 쑥쑥교실투표

쑥쑥교실투표는 교사가 교실에서 장치 하나로 학급 선거, 토의 선택, 토론 입장 선택 같은 투표 활동을 진행할 수 있도록 만든 Rails 기반 감독형 투표 도구입니다.

학생이 각자 계정을 만들거나 개인 단말로 접속하는 방식이 아니라, 교사가 준비한 투표자 명단을 기준으로 현재 투표자를 한 명씩 진행시키며 투표 완료, 미참여, 기권을 기록하는 구조를 목표로 합니다. 전교어린이회 선거, 학급 임원 선거, 학급 토의 안건 선택, 토론 입장 선택처럼 학교 현장에서 실제로 필요한 절차형 투표를 안정적으로 운영하기 위한 프로젝트입니다.

---

## 이 저장소에 대하여

이 저장소는 쑥쑥교실투표의 Rails 애플리케이션입니다.

- 저장소: <https://github.com/ShinJaehun/suksuk_class_vote>
- 기본 브랜치: `main`
- 실행 환경: Ruby on Rails + PostgreSQL
- 주요 대상: 교사, 관리자
- 학생 계정: 초기 MVP에서는 사용하지 않음
- 핵심 방식: 교사 장치 앞에서 투표자 명단 순서대로 1명씩 투표

쑥쑥교실투표의 핵심 방향은 다음과 같습니다.

- 교사가 투표자 명단을 만든다.
- 교사가 투표를 만들고 선택지를 등록한다.
- 투표 시작 시점에 투표자 명단과 선택지 집계를 스냅샷으로 만든다.
- 진행 중인 투표에서는 현재 투표자 한 명만 처리한다.
- 각 투표자는 투표 완료, 미참여, 기권 중 하나의 상태로 확정된다.
- 모든 투표자가 처리되면 투표를 종료하고 결과를 확인한다.
- 투표 진행 이벤트와 무결성 점검을 남겨 중단·복구 상황에 대비한다.

---

## 왜 만들었나

학교에서 투표를 진행할 때는 단순한 설문 도구만으로는 부족한 경우가 많습니다.

특히 학급 선거나 전교어린이회 선거처럼 실제 선거 절차에 가까운 활동에서는 다음과 같은 요구가 생깁니다.

- 투표자 명단을 미리 준비해야 합니다.
- 누가 투표했는지, 누가 미참여했는지, 누가 기권했는지 구분해야 합니다.
- 이미 투표한 학생이 다시 투표하지 못해야 합니다.
- 후보별 득표 수는 정확히 누적되어야 합니다.
- 투표 중간에 문제가 생겨도 현재 상태를 확인하고 재개할 수 있어야 합니다.
- 투표 종료 후 전체 투표자 수, 투표 완료 수, 미참여 수, 기권 수, 득표 수를 확인해야 합니다.
- 교사가 관리하는 투표와 다른 교사의 투표가 섞이지 않아야 합니다.

쑥쑥교실투표는 이런 요구를 반영해, 단순한 “선택지 클릭 설문”이 아니라 **교사가 감독하는 절차형 교실 투표 시스템**으로 설계했습니다.

---

## 사용자 역할

현재 구현의 사용자 역할은 단순하게 유지합니다.

| 역할 | 설명 |
| --- | --- |
| 관리자 | 교사 계정을 만들고 전체 데이터를 관리할 수 있습니다. |
| 교사 | 자신의 투표자 명단과 투표를 만들고 운영합니다. |
| 학생 | 초기 MVP에서는 로그인 사용자가 아니라 투표자 명단의 항목으로 다룹니다. |

학생은 별도 계정, PIN, 개인 단말 없이 교사 장치 앞에서 투표하는 방식으로 처리합니다.

---

## 주요 기능

### 1. 대시보드

로그인한 교사는 대시보드에서 투표자 명단과 투표 관리 화면으로 이동할 수 있습니다.

루트 경로는 대시보드로 연결되며, 로그인하지 않은 사용자는 Devise 인증을 거칩니다.

---

### 2. 투표자 명단

투표자 명단은 실제 투표에 참여할 학생 목록입니다.

투표자 명단은 `ParticipantGroup`으로 관리하고, 명단 안의 개별 학생은 `ParticipantSlot`으로 관리합니다.

투표자 명단에는 다음 정보가 포함됩니다.

- 명단 이름
- 학생 번호
- 학생 이름

교사는 다음 작업을 할 수 있습니다.

- 투표자 명단 생성
- 투표자 명단 수정
- 투표자 명단 삭제
- 학생 1명씩 추가
- 학생 이름 일괄 추가
- 학생 정보 수정
- 학생 삭제

학생 일괄 추가는 한 번에 최대 40명까지 입력할 수 있도록 제한되어 있습니다.

이미 시작 전 투표에서 사용 중인 투표자 명단은 삭제할 수 없습니다. 이는 투표 준비 상태의 무결성을 지키기 위한 정책입니다.

---

### 3. 투표 생성

교사는 투표 제목, 활동 유형, 투표자 명단을 선택해 투표를 만듭니다.

현재 지원하는 활동 유형은 다음과 같습니다.

| 유형 | 의미 | 선택지 명칭 |
| --- | --- | --- |
| 선거 | 후보자 중 한 명을 선택 | 후보자 |
| 토의 | 여러 의견 중 하나를 선택 | 의견 |
| 토론 | 여러 입장 중 하나를 선택 | 입장 |

활동 유형에 따라 화면 문구가 달라집니다.

예를 들어 선거에서는 선택지를 “후보자”라고 표시하고, 토의에서는 “의견”, 토론에서는 “입장”이라고 표시합니다.

---

### 4. 선택지 관리

투표가 아직 시작 전인 `준비` 상태일 때만 선택지를 관리할 수 있습니다.

선거에서는 선택지가 후보자이고, 토의에서는 의견, 토론에서는 입장입니다.

선택지는 자동으로 번호를 부여받습니다.

선거의 경우 이 번호는 후보자의 기호처럼 사용할 수 있습니다.

---

### 5. 투표 시작

투표는 바로 진행되지 않고, 먼저 준비 상태로 만들어집니다.

투표를 시작하려면 다음 조건이 필요합니다.

- 투표가 `준비` 상태여야 합니다.
- 선택지가 2개 이상 있어야 합니다.
- 투표자 명단에 학생이 1명 이상 있어야 합니다.
- 아직 투표자 스냅샷이 만들어지지 않아야 합니다.
- 아직 후보별 집계 정보가 만들어지지 않아야 합니다.

투표를 시작하면 다음 일이 한 번에 일어납니다.

1. 투표자 명단을 기준으로 `PollParticipant` 스냅샷을 만듭니다.
2. 선택지를 기준으로 `PollOptionTally` 집계 레코드를 만듭니다.
3. 첫 번째 투표자를 현재 투표자로 지정합니다.
4. 투표 상태를 `진행`으로 바꿉니다.
5. 투표 시작 이벤트를 기록합니다.

투표 시작 이후에는 원래 투표자 명단이 바뀌더라도 이미 시작된 투표의 투표자 스냅샷은 유지됩니다.

---

### 6. 투표 화면

진행 중인 투표에서는 별도의 투표 화면을 열 수 있습니다.

투표 화면은 학생이 직접 보는 화면에 가깝게 단순하게 구성되어 있습니다.

투표 화면에는 다음이 표시됩니다.

- 현재 투표자 번호와 이름
- 선택지 목록
- 기권 처리 버튼
- 미참여 처리 버튼
- 다음 투표자로 이동하는 버튼

학생이 선택지를 누르면 현재 투표자의 투표가 완료 처리됩니다.

투표 완료 후에는 다음 투표자로 이동할 수 있습니다.

---

### 7. 투표 완료 처리

현재 투표자가 선택지를 고르면 다음 처리가 일어납니다.

1. 현재 투표자를 잠급니다.
2. 선택지 집계 레코드를 잠급니다.
3. 해당 선택지의 득표 수를 1 증가시킵니다.
4. 현재 투표자의 참여 상태를 `투표 완료`로 기록합니다.
5. 투표 완료 이벤트를 기록합니다.

같은 투표자에게 이미 참여 기록이 있으면 다시 투표할 수 없습니다.

---

### 8. 미참여와 기권

모든 학생이 실제로 투표를 완료하는 것은 아닐 수 있습니다.

쑥쑥교실투표는 투표 완료와 별도로 다음 상태를 기록합니다.

| 상태 | 의미 |
| --- | --- |
| 투표 완료 | 선택지를 선택해 투표를 완료함 |
| 미참여 | 결석, 자리 비움 등으로 투표하지 않음 |
| 기권 | 투표권은 있으나 선택하지 않기로 함 |

미참여와 기권은 득표 수를 증가시키지 않지만, 전체 참여 결과에는 별도로 기록됩니다.

이 구조를 통해 “사표”처럼 사라지는 표가 아니라, 투표 결과에서 기권과 미참여를 구분해 확인할 수 있습니다.

---

### 9. 현재 투표자 진행

현재 투표자가 투표 완료, 미참여, 기권 중 하나로 확정되어야 다음 투표자로 이동할 수 있습니다.

다음 투표자는 번호 순서대로 결정됩니다.

아직 현재 투표자가 확정되지 않은 상태에서는 다음 투표자로 넘어갈 수 없습니다.

---

### 10. 첫 미처리 투표자로 재개

진행 중인 투표에서 현재 투표자 정보가 사라진 경우, 첫 미처리 투표자를 찾아 재개할 수 있는 흐름이 준비되어 있습니다.

이 기능은 투표 중단, 예외 상황, 수동 복구를 고려한 구조입니다.

재개는 다음 조건에서 가능합니다.

- 투표가 진행 중이어야 합니다.
- 투표 진행 정보가 있어야 합니다.
- 현재 투표자가 비어 있어야 합니다.
- 미처리 투표자가 남아 있어야 합니다.

---

### 11. 투표 종료

투표는 모든 투표자가 처리된 뒤 종료할 수 있습니다.

종료 조건은 다음과 같습니다.

- 투표가 진행 중이어야 합니다.
- 투표 진행 정보가 active 상태여야 합니다.
- 현재 투표자가 있어야 합니다.
- 현재 투표자가 완료/미참여/기권 중 하나로 확정되어야 합니다.
- 다음 투표자가 없어야 합니다.

투표가 종료되면 투표 상태와 진행 상태가 모두 종료로 바뀌고, 종료 이벤트가 기록됩니다.

---

### 12. 결과 요약

종료된 투표에서는 결과 요약을 확인할 수 있습니다.

결과 요약에는 다음이 포함됩니다.

- 전체 투표자 수
- 투표 완료 수
- 미참여 수
- 기권 수
- 미처리 수
- 선택지별 득표 수
- 최다 득표 선택지

선거에서는 최다 득표 후보, 토의에서는 가장 많이 선택된 의견, 토론에서는 가장 많이 선택된 입장을 확인할 수 있습니다.

동점자가 있으면 여러 명 또는 여러 선택지가 함께 표시됩니다.

---

### 13. 무결성 점검

쑥쑥교실투표는 투표 진행 상태와 결과 상태를 확인하기 위한 무결성 점검 구조를 가지고 있습니다.

무결성 점검은 다음을 확인합니다.

- 진행 중인 투표에 진행 정보가 있는가
- 현재 투표자가 지정되어 있는가
- 후보 수와 후보별 집계 정보 수가 일치하는가
- 다른 투표의 선택지가 잘못 연결된 집계 정보가 없는가
- 투표 완료 수와 후보별 득표 합계가 일치하는가
- 종료된 투표에 미처리 투표자가 남아 있지 않은가

이는 교실 투표에서 중요한 상태 무결성, 중복 방지, 복구 가능성을 확보하기 위한 장치입니다.

---

### 14. 진행 이벤트 로그

투표 중 중요한 사건은 `PollEvent`로 기록됩니다.

현재 기록되는 이벤트는 다음과 같습니다.

- 투표 시작
- 투표 완료
- 미참여 처리
- 기권 처리
- 다음 투표자로 이동
- 첫 미처리 투표자로 재개
- 투표 종료

이벤트에는 투표, 투표자, 수행자, 발생 시각이 남습니다.

단, 비밀투표 원칙을 지키기 위해 이벤트 상세 정보에는 어떤 선택지를 골랐는지에 해당하는 후보자 정보나 선택지 정보가 들어가지 않도록 제한합니다.

---

### 15. 운영 화면 실시간 갱신

진행 중인 투표의 운영 화면은 Turbo Streams를 사용해 일부 영역을 갱신합니다.

투표 제출, 미참여/기권 처리, 다음 투표자 이동이 일어나면 다음 영역이 갱신됩니다.

- 진행 상태
- 이벤트 로그

초기 MVP에서는 교실 투표 운영에 필요한 범위만 Hotwire로 갱신하고, 불필요한 실시간 기능은 성급히 늘리지 않는 방향을 따릅니다.

---

## 투표 흐름 요약

```text
투표자 명단 만들기
  → 투표 만들기
  → 선택지 등록
  → 투표 시작
  → 투표자 스냅샷 생성
  → 첫 투표자 지정
  → 현재 투표자 투표/미참여/기권 처리
  → 다음 투표자로 이동
  → 모든 투표자 처리
  → 투표 종료
  → 결과 확인
```

| `closed` | 종료 |

### PollProgress 상태

| 상태 | 의미 |
| --- | --- |

## 권한 구조

쑥쑥교실투표는 Devise 인증과 Pundit 권한 정책을 사용합니다.

기본 원칙은 다음과 같습니다.

- 로그인하지 않은 사용자는 투표와 명단을 볼 수 없습니다.
- 관리자는 전체 데이터에 접근할 수 있습니다.
- 교사는 자신이 만든 투표자 명단과 투표만 관리합니다.
- 투표 운영, 투표 제출, 미참여/기권 처리, 다음 투표자 이동, 투표 종료는 관리자 또는 해당 투표의 소유자만 수행할 수 있습니다.
- 학생은 시스템 사용자 계정이 아니라 투표자 명단의 항목입니다.

## 개발 과정과 ChatGPT 활용

쑥쑥교실투표는 학교 현장에서 실제로 필요한 투표 절차를 웹 애플리케이션으로 구현한 프로젝트입니다.

처음부터 단순 설문 도구가 아니라, 교사가 투표자 명단을 준비하고, 현재 투표자를 한 명씩 진행시키며, 투표 완료·미참여·기권을 분리해서 기록하는 절차형 시스템을 목표로 했습니다. 전교어린이회 선거, 학급 임원 선거, 학급 토의 안건 선택, 토론 입장 선택처럼 학교 현장에서 실제로 필요한 흐름을 안정적으로 다루는 데 초점을 두었습니다.

개발 과정에서는 ChatGPT를 개발 보조 도구로 활용했습니다. ChatGPT는 코드를 대신 결정하는 도구가 아니라, 투표 절차와 도메인 규칙을 정리하고, Rails 모델과 컨트롤러 책임을 나누며, 테스트해야 할 흐름을 점검하는 보조 도구로 사용했습니다.

## 설계 원칙

### 교사 감독형 투표를 우선한다

초기 MVP에서는 학생이 각자 로그인해서 투표하는 구조가 아니라, 교사 장치 앞에서 한 명씩 투표하는 구조를 우선합니다. 학교 현장의 선거 운영과 중단 복구 가능성을 더 중요하게 보기 때문입니다.

### 학생은 계정이 아니라 투표자 명단이다

학생은 로그인 사용자가 아니라 `ParticipantSlot`과 `PollParticipant`로 관리됩니다. 이를 통해 학생 계정 관리 부담 없이 교실 투표를 운영할 수 있습니다.

### 시작 시점에 스냅샷을 만든다

투표가 시작되면 원본 투표자 명단을 그대로 사용하는 것이 아니라 `PollParticipant` 스냅샷을 만듭니다. 이렇게 하면 투표 시작 이후 명단이 바뀌어도 이미 시작된 투표의 기준은 흔들리지 않습니다.

### 선택지 집계도 별도 모델로 둔다

후보별 득표 수는 `PollOptionTally`에 누적합니다. 투표 완료 처리와 득표 수 증가를 하나의 트랜잭션 안에서 처리해 중복 제출을 막습니다.

### 기권과 미참여를 구분한다

투표하지 않은 상태를 하나로 뭉개지 않고, 미참여와 기권을 구분합니다. 이는 결과 해석과 민주적 절차를 더 명확하게 하기 위한 선택입니다.

### 비밀투표 원칙을 지킨다

이벤트 로그는 투표 운영 상태를 남기지만, 어떤 투표자가 어떤 후보를 선택했는지는 남기지 않도록 제한합니다. 투표 완료 이벤트와 득표 수 집계는 남기되, 선택지 정보는 이벤트 상세에 저장하지 않습니다.

### 상태 무결성과 복구 가능성을 우선한다

선거/투표 기능은 편의성보다 상태 무결성, 중복 방지, 복구 가능성이 중요합니다. 그래서 투표 진행 상태, 참여 기록, 득표 수, 이벤트 로그, 무결성 점검을 분리해 관리합니다.

- 더 정교한 중단 복구 화면
- 감사 로그와 관리자 확인 절차 강화
- 학생 화면과 운영 화면 분리 고도화
- 모바일/태블릿 화면 최적화
- 다중 선거 또는 복수 안건 투표 지원
- 학교 선거 규정에 따른 세부 옵션 추가
